# Canon vs Catalog

**Canon** defines governance primitives and interpretive constraints (authority spine).
It is versioned, immutable per release, and attestable.

**Catalogs / mutation catalogs** define detection/classification logic for signals (implementation).
They evolve frequently as environments change.

In this repo:
- Canon lives in `canon/`
- The DevOps domain pack (including mutation catalog) lives in `domain-pack/`
